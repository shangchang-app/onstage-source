# V1.7.2 修复：试玩版分享卡不能分享给好友

> 基线 `main` @ `8ed4781`。只改「隐藏工位搭子」分享卡的分享方式，不改卡片画面、推荐规则和其他功能。不发布正式站。
>
> **状态：已实现系统分享调用，真机接收待验证。** 自动化测试用替身模拟系统分享面板，只能确认页面交给系统的内容和按钮、提示是否正确；还没有在真机上确认好友能收到。

## 问题

试玩版结果页只有「保存分享卡」：弹窗里只能「下载图片」。要发给好友得先存到相册，再去聊天 App 里找图片。微信里连下载按钮都不显示，只提示长按保存。

## 修改

试玩版是纯静态网页，没有服务器，接不了微信 JS-SDK（需要服务器签名），所以按浏览器能力分三种情况：

| 环境 | 页面做什么 |
|---|---|
| 支持系统分享的手机浏览器（iPhone Safari、安卓 Chrome 等） | 「分享给好友」调用系统分享面板，**带上分享卡图片**和「一句话 + 探索链接」，由用户在面板里选微信、QQ 等。浏览器明确不支持带图片时，改为分享探索链接 |
| 所有浏览器 | 「复制链接」：复制「我在 on stage 的隐藏工位搭子是「…」：…  你的是谁？ + 探索链接」，粘贴到聊天里。剪贴板不能用时显示文字让用户手动复制 |
| 微信、QQ、微博等 App 内置浏览器 | 网页调不起系统分享。**图片上方**提示（390px 手机打开弹窗第一屏可见）：长按图片，**如果菜单里有**「发送给朋友」可以直接发；没有的话选「保存图片」再从相册发送；也可以点右上角「···」分享这个页面，或者复制链接、直接截图。图片用 data: 图片，长按才有菜单 |

### 图片分享失败后

- 每次点击只调一次系统分享，**不自动重试**。
- 带图片的分享打不开（不是用户取消）时，显示独立的「**仅分享链接**」按钮，由用户再点一次，只把不带参数的探索链接交给系统；同时保留「复制链接」「下载图片」。
- 「仅分享链接」也打不开时，明确说没有打开，并给出复制链接、下载图片的办法。
- 用户在分享面板里取消：不提示、不显示「仅分享链接」、不再调用分享。「仅分享链接」时取消，按钮保留，可以再点。
- 提示出现时自动滚到能看见的位置（手机上提示在按钮下面）。

### 其他

- 结果页按钮从「保存分享卡」改为「分享给好友」，弹窗标题同步；分享、复制、下载按钮放在图片正下方。
- 分享出去的只有角色、一句话和探索链接（`/buddy/`，不带参数），不带作答。
- 不显示「分享成功」：系统分享面板关掉后只说「已把分享卡 / 探索链接交给你选的 App」，因为网页无法知道好友是否真的收到。

## 回归测试

`tests/e2e/share-check.cjs`，9 项，已加入 `npm run test:pages`，另有 `npm run test:share`。系统分享面板和剪贴板用替身模拟：

1. 能分享图片：带 PNG 分享卡、一句话、探索链接，不带作答；手机打开弹窗就能看到「分享给好友」；提示不说「成功」。
2. 只能分享链接：改为分享不带参数的探索链接；不显示「仅分享链接」。
3. 用户取消：不报错、不说已分享、不自动重试、不显示「仅分享链接」。
4. 带图片分享打不开：不自动重试；显示「仅分享链接」、复制链接、下载图片；手机上失败提示和「仅分享链接」同时可见；再点仍打不开时说明没有打开。
5. 带图片打不开后再点「仅分享链接」：只交给系统探索链接（不带图片和作答）；提示交给了 App，不说成功。
6. 「仅分享链接」时用户取消：不提示、不再调用分享，按钮保留。
7. 电脑浏览器没有系统分享：不显示「分享给好友」；复制链接内容正确；下载图片可用。
8. 剪贴板不能用：显示文字让用户手动复制。
9. 微信内置浏览器（模拟 UA）：长按提示在图片上方、390px 第一屏可见、用条件式说法；不显示下载和系统分享按钮；图片是 data: 图片；可复制链接。

在修复前的构建上，这些检查都失败（没有「分享给好友」）。`tests/e2e/buddy-check.cjs` 同步了按钮名和微信提示。
