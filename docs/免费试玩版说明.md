日期：2026-11-11　版本：`1.4.1-free.1`
本文是准备工作。按下面的步骤发布之前，没有可以访问的网址。

## 是什么

从正式项目的同一套页面打包出的**纯静态网站**，不需要服务器和数据库，可以免费放到 GitHub Pages。
学生点链接就能浏览机会库和企业页、做岗位体验；作答自动保存在他自己的浏览器里，别人看不到。

| | 免费试玩版 | 正式版（部署准备版，需要服务器） |
|---|---|---|
| 费用 | 0 | 约 7.25 美元/月（Render） |
| 浏览机会库、企业页、岗位体验 | ✓ | ✓ |
| 6 步引导、提示、参考思路、手机端材料抽屉 | ✓ | ✓ |
| 作答保存位置 | 学生自己的浏览器 | 服务器（按访客隔离） |
| 两个页面同时改的冲突保护 | ✓ | ✓ |
| 换设备继续、完成记录、收藏、登录 | ✗ | 接短信登录后 ✓ |
| 后台改内容 | ✗（要改内容需要重新打包） | ✓ |
| 合作意向表单、信息反馈 | ✗（页面会说明暂不支持） | ✓ |
| 你能看到学生做了什么 | ✗（数据只在学生自己的浏览器里） | 只有匿名汇总 |

**作答保存范围**（页面上会写明）：同一个浏览器，至少 7 天内回来可以继续。
- 换手机或电脑、换浏览器、清除浏览器数据、用无痕模式，都会看不到之前的作答。
- 微信里打开和手机浏览器里打开，算两个不同的浏览器。
- 写的是「7 天」而不是更长：部分浏览器（例如 iPhone 上的 Safari）会清理 7 天没有访问的网站数据。

所有内容都是演示内容，标有「示例」。

## 发布步骤（全部免费）

1. 注册 GitHub：github.com → Sign up。
2. 新建仓库：右上角 **+** → **New repository** → 名称填 `onstage` → 选 **Public** → Create repository。
   - 免费账号的 GitHub Pages 只支持公开仓库。仓库里只放打包好的网页文件，不含服务器代码和任何密钥，内容都是演示内容。
3. 把 `dist-pages` 文件夹里的**所有文件**（包括 `.nojekyll`）上传到仓库根目录。
   - 网页上传一次最多 100 个文件，这次一共 210 个文件，建议用 GitHub Desktop 客户端上传。
   - 也可以把 GitHub 连接到 Claude，由 Claude 直接推送。
4. 仓库页面 → **Settings** → 左侧 **Pages** → Source 选 **Deploy from a branch** → Branch 选 `main`、`/ (root)` → Save。
5. 等 1–3 分钟，页面顶部会显示网址：`https://你的用户名.github.io/onstage/`。

**发到群里的专属链接**（直接进入示范体验）：

```
https://你的用户名.github.io/onstage/experiences/ops-returns/
```

如果仓库不叫 `onstage`，需要重新打包：`npm run build:static -- --base=/仓库名`。

## 发链接之前必须做

请 2–3 位在国内的同学用**手机流量**（不开 VPN），分别在微信、QQ、手机浏览器里打开上面的链接，走完一次体验，确认能打开、能保存。
`github.io` 在国内一般可以访问，但速度和稳定性不保证；微信可能提示「在浏览器打开」。打不开时再考虑其他办法。

## 重新打包与检查（技术同事）

```bash
npm ci
npm run build:static          # 输出到 dist-pages/（仓库名为 onstage）
npm run test:pages            # 模拟 GitHub Pages 打开 dist-pages，用 Chromium 实测 11 项
```

试玩版在系统临时目录里的副本中打包，不修改正式项目代码。正式版的构建、测试、部署方式不变。
