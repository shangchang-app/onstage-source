# 上场 · 小范围试用版部署指南（Render）

适用版本：V1.4.1 部署准备版（`1.4.1-deploy.1`）。
本文写于 2026-11-11。平台的价格和页面文字可能变化，**以 Render 当时的页面为准**。

> 这份指南只是准备工作。按下面的步骤操作并验证通过之前，网站**没有上线**，也没有可以访问的网址。

---

## 一、为什么选 Render

| 需要的条件 | 本项目的情况 | Render 是否满足 |
|---|---|---|
| Node.js 22.13 以上（用内置 SQLite） | Next.js 16 + `node:sqlite` | ✓ 支持指定 Node 24 |
| 数据库文件重启、重新部署后不丢 | SQLite 是一个文件 | ✓ 付费实例可以挂「持久化磁盘」。只有挂载目录里的文件会保留，所以数据库放在 `/var/data` |
| 只能单实例运行（多个实例同时写一个 SQLite 文件会出问题） | 单个 `next start` 进程 | ✓ 挂了磁盘的服务平台不允许扩成多实例 |
| 自带 https 测试地址 | — | ✓ `https://服务名.onrender.com` |
| 非技术人员能在网页上操作 | 需要运行管理员登录、备份命令 | ✓ 付费实例在控制台有网页版 Shell，不用装命令行工具 |
| 自动备份 | — | ✓ 磁盘每 24 小时自动快照，保留 7 天 |
| 离中国大陆近 | — | ✓ 可以选新加坡机房 |

**不选免费方案的原因**：Render 免费实例不能挂磁盘，数据会在重启后丢失。所以本项目不能用免费实例。

**备选：Railway**。Hobby 每月 5 美元，含 5 美元用量，本项目大约每月 5–8 美元；新账号有一次性 5 美元试用额度。
它的缺点是：生成管理员登录链接、做备份要装命令行工具（`railway ssh`）；平台说明也写明，它的测试地址不保证在中国大陆能访问。如果你更在意价格，可以用 Railway，用项目里的 `Dockerfile` 部署，并挂载卷到 `/data`。

## 二、费用

| 项目 | 价格 | 说明 |

## 三、部署前要你自己注册的

1. **GitHub 账号**（github.com，免费）。用来存放代码，Render 从这里读取。
2. **Render 账号**（render.com → Get Started，可以用 GitHub 账号登录）。
3. 一张**能付美元的银行卡**（Visa / Mastercard）。Render 创建付费服务时需要绑卡。

## 四、部署步骤

### 1. 把代码放到 GitHub（私有仓库）
1. 登录 GitHub → 右上角 **+** → **New repository**。
   - 名称例如 `onstage`，选 **Private**，直接点 **Create repository**。
2. 在新仓库页面点 **uploading an existing file**，把解压后的项目文件夹**里面的所有内容**拖进去，然后点 **Commit changes**。
   - 交付包里不含 `node_modules`、数据库和密钥，可以直接上传。
   - 如果网页上传失败（文件太多），用 GitHub Desktop 客户端上传。

### 2. 在 Render 用 Blueprint 创建服务
1. 登录 Render → 右上角 **New** → **Blueprint**。
2. 连接 GitHub，选择刚才的仓库。Render 会读取项目里的 `render.yaml`。页面上应该显示：
   - 一个网页服务 `onstage-trial`；
   - 机房 Singapore；
   - 规格 0.5c-512mb；
   - 1 GB 磁盘挂在 `/var/data`。
3. 确认费用后点 **Apply / Deploy Blueprint**。第一次构建大约 3–6 分钟。
4. 部署完成后，服务页面顶部会显示网址，例如 `https://onstage-trial.onrender.com`。名字被占用时 Render 会加一串后缀，以页面显示为准。

`render.yaml` 已经设置好的环境变量（一般不用改）：

| 变量 | 值 | 作用 |
|---|---|---|
| `DATABASE_PATH` | `/var/data/onstage.sqlite` | 数据库放在持久化磁盘上 |
| `DEMO_CONTENT` | `seed-if-empty` | 第一次启动、数据库为空时写入演示内容，全部标为「示例」。以后不会重复写入，也不会覆盖已有内容 |
| `SESSION_DAYS` | `30` | 访客 30 天内回来可以继续，每次打开自动续期 |
| `AUTH_SECRET` | 平台自动生成 | 以后接短信登录时用 |
| `NODE_VERSION` | `24` | — |

`APP_ORIGIN`（网站地址）**不用填**，程序会自动使用 Render 分配的 https 地址。

### 3. 部署后自检（5 分钟）
1. 打开 `https://你的地址/api/health`，应该看到 `{"ok":true}`。
   - 如果看到「服务配置不完整」，到 **Logs** 页面看具体原因（会写明缺什么）。
2. 打开首页，确认：
   - 页面右上角显示「试用版」，没有「登录」按钮；
   - 内容带「示例」标记；
   - 页面顶部**没有**「本地开发 / 测试环境」提示条。
3. 进入岗位体验，写一句作答，等出现「已保存」。刷新页面，内容还在。
4. 换一个浏览器（或无痕窗口）打开同一个体验：应该看不到刚才的作答（访客之间隔离）。

### 4. 登录后台（管理员一次性链接）
试用版不开放手机登录，管理员用「一次性链接」登录。链接只能在服务器上生成，网站上没有任何入口。
1. Render 服务页面 → 左侧 **Shell**。
2. 输入下面的命令，回车（手机号只用作管理员账号的标识，不会发短信）：
   ```
   npm run admin:link -- 你的手机号
   ```
3. 复制输出的链接，在**你自己的浏览器**里打开，点「以管理员身份登录」，就会进入「内部后台」。
   - 链接 15 分钟内有效，只能用一次；登录状态 12 小时后失效，需要时再生成一条。
   - 链接相当于临时密码：**不要发到群里、不要截图**。
   - 取消某个管理员：`npm run admin -- 手机号 --revoke`。

### 5. 备份与恢复
- **自动**：Render 每 24 小时给磁盘做一次快照，保留 7 天。可以在服务的磁盘（Disk）设置里查看和恢复（以控制台为准）。注意：恢复快照会丢掉快照之后的所有改动。
- **手动备份**（网站运行中也能做，不影响访问）：在 Shell 里运行 `npm run backup`，备份存在 `/var/data/backups/`；运行 `npm run backup -- --list` 查看已有备份。
- **自动保护**：以后更新代码，如果带来数据库结构变化，程序会在升级前自动备份一份（文件名含 `before-migration`）。
- **从手动备份恢复**：
  1. 在 Shell 里运行 `npm run restore -- /var/data/backups/备份文件名.sqlite`。
  2. 重启服务（服务页面 **Manual Deploy** 菜单里的 Restart，以控制台实际名称为准）。
  3. 启动时自动换成备份；原来的数据库另存为 `onstage.sqlite.before-restore-时间`，**不会删除**。
- **注意**：备份和数据库在同一块磁盘上。重要节点（比如试用结束）可以请技术同事把备份文件下载到本地另存。

### 6. 以后更新网站
把修改后的代码上传到同一个 GitHub 仓库，Render 会自动重新部署。部署时网站会停几秒，这是为了保护数据库文件不被两个版本同时写入。

### 7. 以后绑定你自己的域名（需要时）
1. Render 服务 → **Settings** → **Custom Domains** → 添加，例如 `try.你的域名.com`。
2. 按 Render 页面提示，到你买域名的网站（如阿里云、腾讯云）的「域名解析」页面，添加一条 CNAME 记录。
3. Render 服务 → **Environment** → 新增 `APP_ORIGIN = https://try.你的域名.com` → 保存，服务会自动重启。
   - 原来的 onrender 地址仍会自动保留可用，不用一起写进去。
4. 服务器在新加坡，用你自己的域名**不需要 ICP 备案**。注意：域名在国内注册商那里需要完成实名认证才能解析。

## 五、国内访问：发到群里之前必须实测

已经核实的情况：
- 平台测试地址（`*.onrender.com`、`*.up.railway.app`、`*.fly.dev`）都是很多人共用的域名，在中国大陆**经常被间歇性阻断**。Railway 官方答复里明确写了无法保证中国大陆能访问它的测试地址。Render 没有找到官方说明，按同样的风险对待。
- 微信、QQ 内置浏览器打开海外网站时，可能会提示风险，或者要求「在浏览器打开」。这无法事先保证，只能实测。

**怎么测**：请 2–3 位在国内的同学用**手机流量**（不开 VPN），分别在下面三个地方打开链接，走完一次岗位体验，确认能保存：
- 微信里（发给对方，在聊天里点开）；
- QQ 里；
- 手机自带浏览器。

**如果打不开或很慢**：改用你自己的域名（见第 4 节第 7 步），然后再测一次。自有域名不和别人共用，一般比平台测试地址稳定，但也不能 100% 保证。如果要在国内长期稳定访问，需要国内服务器加 ICP 备案（要几周，不在这次范围内）。

## 六、试用版给学生的保存规则（建议写进群公告）

- 不需要注册或登录，打开就能浏览、做岗位体验。
- 作答自动保存在**你自己的浏览器**里：同一个浏览器 30 天内回来可以继续。
- 以下情况会看不到之前的作答：换手机或电脑、换浏览器、清除浏览器数据、用无痕模式。
  - 微信里打开和手机浏览器里打开，算两个不同的浏览器。
- 试用期间暂不能保存「完成记录」和收藏。
- 别人看不到你的作答，企业也看不到。请不要在作答里填写手机号、身份证号等个人信息。
- 内容标有「示例」的都是虚构的，不代表真实企业或真实招聘。
