# 「你的隐藏工位搭子」题目与规则说明（题目版本 v2）

> 这是一个**趣味情境探索**，属于娱乐产品设计。规则没有心理测量效度，不判断人格或职业能力；结果不用于企业筛选、能力评分，也不算岗位实践完成记录。

- 题目、选项、角色映射、结果文案、版本号：`src/lib/buddy/config.ts`（全部配置在这一个文件里）
- 判定规则：`src/lib/buddy/engine.ts`（纯函数，没有随机数、时间或网络）
- 本机进度与题目版本处理：`src/lib/buddy/store.ts`
- 完整规则表（每个选项的位置、id、加分，穷举分布，并列人数，旧截断规则的影响，13 条可复现路径）：`docs/V1.7-隐藏工位搭子-规则表.md`，由 `npm run buddy:rules` 自动生成
- 规则测试：`tests/buddy.test.ts`（穷举全部 65,536 种作答）；浏览器测试：`tests/e2e/buddy-check.cjs`

## 1. 情境与时间线

一个连贯的虚构小项目：实习第三周，4 人小组周一到周五做一份「开学季校园推广」方案，原定**周五下午三点**向主管汇报。

| # | 阶段 | 时间 | 情境 |
|---|---|---|---|
| 1 | 接任务 | 周一 | 主管要方案，周五下午三点汇报，具体要什么没多说 |
| 2 | 找材料 | 周一–周二 | 资料一下子堆满共享文件夹 |
| 3 | 探索方案 | 周二 | 小组想出三个方向 |
| 4 | 发现错误 | 周三晚上 | 发现 PPT 里最关键的数字口径错了 |
| 5 | 协调分歧 | 周四上午 | 两位组员为方向争起来 |
| 6 | 时间缩短 | 周四下午 | 汇报从周五下午三点**提前到周五早上九点** |
| 7 | 应对意外 | 周五早上八点半 | 演示用的在线文档打不开 |
| 8 | 完成复盘 | 汇报后 | 主管说「方向可以，细节再打磨」 |
| 区分题 | 收尾 | 周五下午 | 项目告一段落，离下班还有一个小时 |

每题 4 个选项，每个选项都写成一个说得通的做法，也都有代价。没有标准答案，也没有「最佳人格选项」。

第 4 题的「另找证据」选项要求**先跟大家说明口径用错了、改成月活**，再另找一份更能说明问题的证据；不能被读成用新指标绕开错误。

## 2. 选项 id 与显示顺序

- 每个选项有一个固定的语义 id（例如 `recalc-first`、`fix-then-evidence`）。**计分、存储、依据只认 id**，不认它在页面上排第几。
- `config.ts` 里的数组顺序就是页面上的显示顺序，固定不变、不随机，返回和刷新都一样。
- 6 个「另辟蹊径」选项（★）在第 2–7 题里分别排在第 3、1、4、2、3、1 个位置，没有都放在同一个位置；测试会检查同一位置的 ★ 选项不超过 2 个。

## 3. 计分与判定

1. 每个选项给 1 个常规角色 **+2**、另 1 个常规角色 **+1**。12 个常规角色在 8 题里各有 2–3 个 +2 选项。
2. 8 题全部作答后才计算。
3. **隐藏角色**：★ 选项选了 **≥ 4 次** → 不按物种出牌的鸭嘴兽。只看这个行为组合，与分数高低无关；鸭嘴兽不参与计分，不靠分享或付费解锁。
4. 否则累加 12 个常规角色的分数，**第一名唯一** → 直接得到第一名。
5. **第一名并列** → 追加 **1 道**区分题，**并列的角色全部列出**（穷举里最多 7 个），每个角色一个做法，不显示动物名；选哪个，结果就是哪个。区分题选项按角色配置顺序排列，这只影响显示位置，不影响谁能进入区分题。
6. **返回修改**：改了任何一题都重新计算。区分题答案连同当时的候选一起保存；候选变了，旧答案作废，需要重新回答。

同样的作答（含区分题答案）一定得到同样的结果。

### 关于「超过三个角色并列」（v1 的问题）

v1 预览版的区分题最多只放 3 个角色：并列超过 3 个时，先按「拿到 +2 的次数」、再按**角色在配置里的顺序**截掉多出来的。按 v2 题目穷举，并列超过 3 个的组合有 **2,040 种（3.1%）**。被截掉的次数如下，排在配置后面的猫头鹰、兔子、刺猬、企鹅被截得最多，等于把数组顺序当成了没有解释的优先级：

| 角色 | 被截掉 | 角色 | 被截掉 |
|---|---|---|---|
| 半夜突然想通的猫头鹰 | 596 | 自带时区的猫 | 284 |
| 耳朵先收到消息的兔子 | 581 | 正在潜水的水獭 | 124 |
| 有边界的小刺猬 | 408 | 什么都想拆开的浣熊 | 67 |
| 自带集合点的企鹅 | 353 | 给大家留气口的海豹 | 17 |
| 同时伸出八只手的章鱼 | 304 | 开十个标签页的狐狸 | 3 |
| 口袋塞满 Plan B 的松鼠 | 2 | 叼着 Demo 的边牧 | 0 |

**v2 的处理**：并列的全部进入区分题，不截断，由用户自己选。代价是极少数情况下区分题选项会比较多（5 人并列 0.7%，6 人 0.2%，7 人 6 种组合）。

## 4. 结果里的「依据」

只引用用户这次真正选过的选项原文：

- 常规角色：给这个角色加分最多的两个选项（同分按情境顺序）。经区分题得到的结果，第二条换成区分题的答案。
- 鸭嘴兽：前两次 ★ 选择，并写出一共选了几次。

结果页统一用「在这次情境中，你……」，不说用户「就是」某种人。不展示分数、百分比、稀有度或排名。

## 5. 题目版本与旧进度、旧结果

- 版本号：`RULES_VERSION`（当前 **v2**），改动记录在 `RULES_CHANGELOG`。**改了题目、选项、加分或判定规则，就必须改版本号。**
- 本机存储（`onstage-buddy:v1`，键名不变）里记着 `schema: 2` 和 `rulesVersion`。到达结果页时，会存一份**结果快照**（角色、一句话、两条依据原文、版本、时间）。
- 打开模块时：
  - 版本一致 → 照常恢复。
  - 版本不一致（含 v1 预览版的旧格式）→ **不用新规则重算旧作答**，也不把旧选项 id 当成新选项。说明页提示「题目已经更新过」，旧作答的题数写明；有旧结果快照的，提示「上次的结果『X』按当时的题目得出，原样保留」，可以打开查看（内容和当时一模一样）。存储里的旧数据**在用户点「按新题目重新开始」并确认之前不会被改写**。
  - 确认重新开始后，旧结果快照移到 `previous` 里继续保留（最多 5 条），说明页底部可以打开。
- v1 只在本地预览包里出现过（提交 `b9a8bb5`–`48b26ef`），格式里没有结果快照，所以 v1 的结果无法原样显示；界面只说明作答来自旧版题目，不会给出一个换算后的新结果。
- 注意：正式站 `/onstage/` 和预览 `/onstage-source/` 同源、共用这份数据，版本号就是用来区分两边题目不同的情况。

## 6. 穷举检查（只检查配置，不代表真实人群）

把 65,536 种作答各算一次（区分题按每个候选机会相同估算）：12 个常规角色各占 7.0%–9.6%（平均 7.7%），鸭嘴兽 3.8%，36.3% 的组合需要区分题；固定任意一道题的任意一个选项，剩下的组合仍能得到 ≥ 10 种不同结果；13 个结果都有不需要区分题的可复现路径。真实用户不会随机作答，这些数字**不能**说明结果准确或有效。

## 7. 推荐的岗位体验

每个角色配一个站内真实存在的体验，推荐卡上标明类型：

- **简版练习**：只有任务和参考思路，没有复盘，也不生成成果；
- **完整实践 · 短版**：收到任务、看材料、给方案、看复盘；
- **完整实践 · 完整版**：示范、独立练习、迁移练习，最后保存成果。

推荐的是简版练习时，再给一个完整实践（`rec.full`）。体验不存在或没发布时只给体验列表，不做假入口。所有结果都附「也看看其他方向」。

| 角色 | 推荐 | 另给的完整实践 |
|---|---|---|
| 狐狸、企鹅 | `my-quick`（简版练习） | `ai-eval` |
| 水獭 | `ops-returns-deep`（完整版） | — |
| 边牧、章鱼 | `ops-returns`（短版） | — |
| 猫、猫头鹰 | `ai-eval`（完整版） | — |
| 松鼠 | `yc-std`（简版练习） | `ops-returns` |
| 海豹、刺猬 | `xt-std`（简版练习） | `ai-eval` |
| 浣熊 | `yc-quick`（简版练习） | `ops-returns-deep` |
| 兔子 | `yc-quick`（简版练习） | `ops-returns` |
| 鸭嘴兽 | `xt-std`（简版练习） | `ops-returns-deep` |

## 8. 改题目时

改 `config.ts` 后：改 `RULES_VERSION` 并记一笔 → `npm test`（重新穷举，检查可达路径、隐藏触发、依据准确、分布范围、★ 位置、版本处理）→ `npm run buddy:rules`（重新生成规则表）。角色名称和一句话是已确定的，测试会核对，不要改。
