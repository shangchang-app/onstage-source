## 2. 视觉规范落在哪里

- 全部在 `src/app/globals.css`：开头的 `:root` 令牌（颜色、圆角、阴影、焦点光圈），以及按钮、标签、卡片、表单、表格、步骤条、抽屉、弹窗、提示框、后台标签等通用类。
- 页面组件只改了三处类名：删除按钮加 `btn-danger`（红色描边，二次确认用红底），体验类型标签「短版」用描边、「完整版」用黑底。
- 颜色：底色 `#F5F4F1`，卡片白色，文字 `#151515`，辅助文字 `#44403B` / `#5E5A54`。原来的橙色（`#CF4410`、`#F26A2E`、`#FDEDE3`）已全部删除，静态版测试会检查样式表里不再出现。
- 语义色只用于状态：成功绿、提醒琥珀、错误红。提示框左侧有 ✓ / ! / × / i 图标，规则检查开头有 ✓ / !，不只靠颜色区分。
- 可读性：正文 16px；辅助文字 14px；最小 13px（时间、底栏文字）。对比度：正文 16.6:1，辅助文字 9.4:1 和 6.2:1，禁用按钮文字 5.3:1，三种语义色对各自底色都在 5.6:1 以上。禁用按钮改成灰底深灰字，不再用半透明。
- 焦点：所有可聚焦元素 2px 黑色描边；输入框聚焦时黑框加浅灰光圈。
- 动物 emoji 保持原色，没有重画。

## 3. 趣味入口为什么没有按钮

动物模块还没做完。没有配置 `NEXT_PUBLIC_FUN_URL` 时，首页只显示预告卡和「还在制作中，做好后在这里打开」，**不显示「看看是谁」按钮**。模块做好后，打包时设置这个变量（站内地址，以 `/` 开头），按钮就会出现，不用改代码。

## 4. 本地存储（预览和正式版共用）

正式站 `https://shangchang-app.github.io/onstage/` 和预览 `https://shangchang-app.github.io/onstage-source/` 是**同一个源**。浏览器的 localStorage 只按源区分，不按路径区分，所以两个网址读写的是同一份数据。**不能假设不同路径天然隔离。**

| 键 | 内容 | 谁写 | V1.7 是否改动 |
|---|---|---|---|
| `onstage-free:v1` | 草稿库：`owner`、`drafts`、`recoveries`、`schema` | V1.4.1、V1.6、V1.7 | 否 |
| `onstage-works:v1` | 成果：`{ schema: 1, works: [...] }` | V1.6 起 | 否 |
| `onstage:backup:<owner>:<体验 id>` | 本机暂存的作答 | 各版本 | 否 |
| `onstage:reflection:<体验 id>` | 做完后的「感受」 | 各版本 | 否 |
| `onstage:migrated:v16` | 旧键迁移完成的标记 | V1.6 起 | 否 |

**迁移**：V1.7 没有新的迁移。沿用 V1.6 的一次性迁移：V1.4.1 的 6 步作答**复制**到完整版（`ops-returns-deep`），原处保留，草稿库写上 `schema: 2`，以后不再迁移。

**回滚兼容（已用自动测试证明，见下）**：

- V1.4.1 读写草稿库时保留它不认识的字段，所以 `schema: 2` 不会丢，再升级时**不会二次迁移、不会覆盖**完整版里在新版写的内容。
- V1.4.1 不读也不写 `onstage-works:v1` 和 `onstage:migrated:v16`，成果和标记原样保留。
- V1.4.1 保存 `ops-returns` 时，会保留新版短版写在同一份草稿里的作答（`plan.*`），不会删除。
- 回滚期间在 V1.4.1 里新写的作答留在 `ops-returns` 原处；再升级后不会自动复制到完整版（迁移只做一次），但会包含在导出的备份里。

## 5. 测试

| 测试 | 命令 | 环境 |
|---|---|---|
| 单元测试（47 项） | `npm test` | — |
| 静态版测试（25 项，含 V1.7 新增 4 项） | `npm run test:pages` | 每项都用**全新、隔离的浏览器环境**（Playwright 新 context），互不共用本地数据 |
| **同源升级与回滚**（5 步） | `npm run test:rollback -- <旧版目录> <新版目录>` | 单独执行。同一个本机源下：`/onstage/` 放 V1.4.1 发布包、`/onstage-source/` 放新版；每一步把 localStorage 全量存成 JSON 备份（`test-results/rollback/`） |

同源回滚测试的步骤：

1. 全新浏览器，本地数据为空。
2. 旧版 V1.4.1 写两格并保存。
3. 新版：完整版读到旧草稿；在完整版、短版各写入；存一份成果。
4. **回到旧版**：旧作答都在、能继续保存；新版的完整版草稿逐字节不变；短版作答、成果、迁移标记都还在；没有任何键被删除。
5. **再回到新版**：完整版仍是新版写的内容（没有被旧版或二次迁移覆盖）；短版作答和成果都在；旧版期间的改动留在原处。

CI 每次推送都会下载线上发布包（核对 SHA256 `10d61ad4…4f23`）跑一遍这个测试。
