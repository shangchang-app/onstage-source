## 2. 整合方式

1. 从 PR #2（0e9e1df，基线就是 `main` 的 948da0a）新建整合分支 `integration/v1.7-buddy-growth`。
   这样做是因为 PR #2 的 `ci.yml` 和 `preview.yml` 改动已经在 GitHub 上了，整合分支的新提交都不改 `.github/`，可以用仓库里的一次性导入方式推上去。
2. `merge --no-ff` PR #1（dd1af1c）。
   - `package.json` 冲突：两边的新测试都保留，`test` 里同时有 `tests/buddy.test.ts` 和 `tests/overseas-growth.test.ts`。

   - 合并结果和「从 main 先合 PR #2、再合 PR #1」完全一样（文件树一致，已核对）。
3. 下面第 4–6 步是整合时新加的提交。
4. 两处公共体验细节修复：`work.tsx`、`output.tsx`（见第 3 节）。
5. 出海增长内容补充比较口径（见《出海增长体验-内容说明.md》第 8 节）。
6. 新增整合路径检查 `tests/e2e/integration-check.cjs`，并加入 `test:pages`。`ci.yml` 的合并前测试会一起运行。

两条开发线的提交都原样保留在历史里，没有用整包覆盖。整合 PR 合并后，PR #1 和 PR #2 的提交都包含在 `main` 里。

| 问题 | 修改 |
