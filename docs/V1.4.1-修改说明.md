# 上场 V1.4.1 修改说明

日期：2026-11-11　状态：**本地开发版本，未部署，网站未上线**
基于 V1.4 继续，没有重建项目，没有扩展人才库、AI 评分或企业招聘后台。

## 一、授权限制被「已截止」覆盖（已修复，服务端）

**问题**：`content()` 先根据企业授权、企业状态、岗位确认把状态设为 offline / pending，随后的截止日期判断又把它覆盖成 expired。`publicContent()` 允许返回 expired 内容，于是已停止展示的岗位会重新暴露完整详情。另外发现，**岗位修改后尚未确认（pending）× 已截止**也会被覆盖，未确认的改动因此泄露。

**修复**（`src/server/service.ts`）：
- 新增 `blockedReason()`，把「是否允许公开」和「是否已截止」分成两步：
  1. 先判断是否允许公开。内容未发布（草稿 / 待确认 / 下架）、企业未授权、企业不在展示中、岗位当前版本未确认，任一成立就停止展示。
  2. 只有允许公开的内容，才继续判断是否已截止。已截止只关闭投递 / 报名入口。
- 列表、详情、收藏、旧链接、关联推荐、投递接口都调用同一个 `content()`，所以行为一致。
- 停止展示的内容只返回 `{status, data:{title:'这项内容暂不可用'}}`，不带任何字段。
- 学生自己的历史完成记录读取的是快照，不受影响。

**组合回归测试**（`tests/service.test.ts`，全部在服务端验证）：
- 「已截止」分别叠加以下情况：企业撤销授权、企业下架、岗位待确认、岗位下架、岗位草稿。每种都验证：
  - 详情只剩标题，职责、要求、薪资、投递地址、来源、截止日期、企业编号都不出现；
  - 列表里不显示；
  - 投递入口和新增收藏都被拒绝；
  - 已有收藏里只显示「暂不可用」。
- 正常发布、授权有效 × 已截止：仍可看详情，投递入口关闭，确认依据和授权依据不公开。
- 企业撤销授权后，学生自己的历史完成记录仍可查看。
- 已确认：把顺序改回旧写法时，其中 3 项会失败；修复后全部通过。

## 二、后台内容维护（已补齐）

`/admin` 现在按标签分为：岗位体验、企业、招聘、赛事、合作意向、反馈、操作记录。

| 内容 | 新建 | 编辑 | 预览 | 状态操作 |
|---|---|---|---|---|
| 企业 | ✓ | ✓ | ✓（学生端详情样式） | 登记授权与依据；没有授权不能发布；发布 / 下架 |
| 招聘 | ✓ | ✓ | ✓ | 记录企业确认 → 发布；下架。未确认不能发布 |
| 赛事 | ✓ | ✓ | ✓ | 来源、截止日期、报名地址；发布 / 下架 |
| 岗位体验 | ✓（基本信息 + 内容模板） | 在版本里编辑 | ✓（详情页 + 各步骤，可试填但不保存） | 版本：提交审核（必须写来源）→ 通过 / 退回 → 发布；下线 / 上线 |

- 所有表单都走原有接口：服务端校验和管理员权限都是同一套，普通账号调用会被拒绝（测试覆盖）。
- **保存 ≠ 核验**：
  - 新建内容默认是草稿，不公开。
  - 修改已有的企业、招聘或赛事后，状态回到「待确认 / 待重新发布」，按规则确认、发布后才会公开。
  - 体验版本保存只更新草稿，线上内容不变。
- **企业共创**：版本必须关联企业，并记录企业的实际确认才能发布；修改内容会清空已有确认。关联企业未授权展示时也不能发布。
- **演示内容**：每个表单都有「示例 / 演示内容」勾选项，勾选后学生端显著标注「示例」。
- **体验章节**：没有做富文本编辑。基本信息用普通表单；章节保留 JSON 编辑，配了：
  - 完整引导 / 简版两套模板（模板本身能通过校验）；
  - 「检查格式」按钮；
  - 服务端校验错误翻译成中文路径（如「章节内容 › 作答小步 › 第 1 项 › 作答框」）；
  - 预览，以及未保存提醒。
- **未保存保护**：
  - 有修改时显示「有未保存的修改」。
  - 切换标签、点取消、收起版本时弹窗确认；关闭或刷新页面时浏览器提示。
  - 出错的字段标红（`aria-invalid`）。
- **并发编辑**：
  - 企业、招聘、赛事沿用内容版本号；体验版本新增修改计数（迁移 004）。
  - 后保存的一方会看到「已被其他管理员修改」，自己的修改留在页面上，不会覆盖对方。

## 三、「允许只看不做」统一

- 简版练习也可以直接「查看参考思路」，不用先答完。参考内容由服务端返回，页面上需要学生主动点开；公开列表接口仍不带参考。
- 浏览、看参考、作答、完成分开记录：
  - 简版作答页显示：已浏览 / 已看参考思路 / 已作答 x/y / 已完成实践。
  - 「我的」里显示「已看参考思路 · 已作答 x/y · 未完成实践」。
- 只浏览、只看参考，都不会生成完成记录：前端完成按钮不可用，服务端返回 INCOMPLETE。
- 没有新增评分、排名或能力标签；作答仍然只有本人可见。
- 顺带修了一个 V1.4 的问题：简版练习在没选选项时输入理由，文字会被清空。

## 四、手机端查看材料

- 宽度 ≤960px 时，作答页顶部有一条吸顶小栏：显示当前步骤和保存状态，以及「查看材料（4）」按钮。每个作答小步旁边也有「查看材料」。
- 材料从底部抽屉弹出，复用原有的无障碍弹窗：焦点进入抽屉，Tab 不离开，Esc 或「关闭」退出。关闭后**焦点回到刚才作答的输入框**，内容不变。
- 表格只在自己的容器里横向滚动，抽屉和页面都不横向溢出。
- 手机上站点顶栏不再吸顶，避免和材料栏叠在一起。浏览器自动滚动到输入框时，会给顶部材料栏和底部导航留出空间，测试检查了输入框没有被遮挡。
- 顺带修了两处桌面端问题：
  - 作答页的顶部步骤栏被站点顶栏盖住；
  - 右侧材料表格把侧栏撑宽、被截断。

## 五、测试可以在干净环境复跑

| 问题 | 处理 |
|---|---|
| Playwright 没有声明 | `devDependencies` 锁定 `playwright@1.63.0`，写进 `package-lock.json`；README 写明 `npx playwright install chromium` |
| `test:e2e` 依赖 Bash | 改为 Node 脚本 `tests/e2e/run.mjs`，Windows / macOS / Linux 通用 |
| `pkill -f "next dev"` 可能误杀 | 只按进程号结束本次启动的子进程。Windows 用 `taskkill /T`，其他系统结束进程组。运行时会起一个命令行里也带 `next dev` 的「其他项目」进程做自检 |
| 服务端测试用 `npx` 启子进程 | `scripts/seed.ts` 改为可导入的 `seed(store)`，测试在进程内调用；不再使用 `npx` 或子进程 |
| 固定端口、既有目录 | 端口占用检查，可用 `--port` 指定，不指定就从 3200 起自动找空闲端口；结果目录自动创建；构建目录独立 |
| 可能碰到用户数据库 | 测试库建在系统临时目录，结束后删除，不读写 `data/` |
| 失败 / 超时 | 启动失败、用例失败、超时都返回非零退出码，并清理本次进程 |
| 开发工具浮标挡截图 | `next.config.ts` 关闭 `devIndicators` |

## 七、尚未完成 / 上线前阻塞

**仍未完成**：
- 账号注销与个人数据导出。
- 体验章节的可视化编辑（目前是 JSON 加模板）。
- 后台内容的删除（目前用下架代替，保留历史）。
- 其余 4 个简版练习的完整引导版本。

**上线前阻塞**（和 V1.4 相同，本轮没有宣称完成）：
1. **真实短信**：选定服务商，按它的接口调整 `HttpSmsProvider`，配置网关和令牌。
2. **正式协议**：用户协议、隐私政策（个人信息保护法）；境内部署还需要 ICP 备案。
3. **账号**：账号注销与数据导出。
4. **托管与备份**：SQLite 需要单实例和持久磁盘，并定期备份；正式域名和 HTTPS；设置 `AUTH_SECRET`。
5. **真实内容接入**：生产库不写入演示数据。真实企业、岗位、赛事要通过后台录入，并取得企业的实际授权和确认。示范体验建议请真实从业者审阅。
6. **兼容性**：Windows 上的测试运行器，以及 Safari / iOS、Android 真机、屏幕阅读器，都需要补测。

**是否适合小范围学生试用**：公开数据问题已修复，管理员可以通过页面维护内容，测试可以复跑。在本机或内网、用模拟登录的测试环境里，可以组织小范围试用。如果要让学生用自己的手机号登录，先完成阻塞项 1、2、4。
