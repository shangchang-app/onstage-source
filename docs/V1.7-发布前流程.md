# V1.7 发布前流程：合并请求测试、部署后检查、发布步骤

适用于「隐藏工位搭子」整合版（分支 `v1.7-buddy-fix`）。**不自动合并，不覆盖正式站。**

## 1. 三个环境，别混

| | 网址 | 由谁更新 |
|---|---|---|
| 正式站 | `https://shangchang-app.github.io/onstage/` | 仓库 `shangchang-app/onstage`，只有手动换发布包才更新（当前 V1.4.1） |
| 预览 | `https://shangchang-app.github.io/onstage-source/` | 本仓库合并到 `main` 后，`preview.yml` 自动部署 |
| 合并请求 | 没有网址 | `ci.yml` 只在 GitHub 的临时机器上构建和测试，不部署 |

正式站和预览同源，浏览器本地数据共用（见《V1.7-修改说明.md》第 4 节）。

## 2. 合并前：PR 测试（`ci.yml`）

触发：每个指向 `main` 的合并请求。权限只读（`contents: read`），用 `pull_request` 而不是 `pull_request_target`，所以来自 fork 的合并请求也拿不到密钥、不能写仓库；检出时不保留令牌（`persist-credentials: false`）。不建 Release，不部署。

| 任务 | 检查内容 |
|---|---|
| `unit` | `npm ci`、类型检查、单元测试（含隐藏工位搭子规则穷举 65,536 种作答）、规则表是否和配置一致 |
| `pages` | 线上路径 `/onstage` 和预览路径 `/onstage-source` 各构建一次，各跑原有静态版测试和隐藏工位搭子浏览器测试；二维码**内容**（从下载的分享卡 PNG 里解码，核对网址）和二维码**路径在本机能打开**（`check-qr-target.mjs --local`）；同源升级与回滚（线上 V1.4.1 发布包 → 本次 → V1.4.1 → 本次） |

**不检查**线上预览网址能不能打开、线上提交号：那时还没部署。工作流摘要会写明「未检查（不是通过）」。

## 3. 合并后：部署与部署后检查（`preview.yml`）

合并到 `main` 后自动：重跑全部测试 → 打包 → 发预发布 Release（`build-<提交号>`）→ 部署预览 → **`verify-deployed-preview`**：真正打开 `https://shangchang-app.github.io/onstage-source/buddy/`，要求 200、是隐藏工位搭子页面，页脚和 `version.json` 都是这次的提交；最多重试 12 次（GitHub Pages 生效有延迟）。

这一步通过之前，不要分享预览版的分享卡。它只证明服务器能打开；手机扫码、微信内打开、大陆移动网络仍需真机确认。

## 4. 发布到正式站（手动，等预览验收后）

正式站的二维码指向 `https://shangchang-app.github.io/onstage/buddy/`，这个页面**换上发布包之后才存在**。

1. 在本仓库 Releases 里找到合并后那次构建 `build-<提交号>`，下载 `onstage-site-1.7.0-<提交号>.zip` 和 `.sha256`，核对校验值。
2. 在 `shangchang-app/onstage` 删掉旧的 zip、上传新的 zip，等它的 Actions 变绿。
3. 发布后检查（在本仓库目录里运行）：
   ```bash
   node scripts/check-qr-target.mjs https://shangchang-app.github.io/onstage/buddy/ --commit <提交号> --retries 10
   ```
   并打开 `https://shangchang-app.github.io/onstage/version.json` 核对提交号。
4. 用真手机（iPhone、安卓各一台）和微信扫一张分享卡，确认能打开。
5. 回滚：用 `shangchang-app/onstage` 提交 `5eed8ae` 里的 `site.zip`（sha256 `10d61ad4…4f23`）替换（见《V1.6-验收与发布.md》第 5 节）。回滚后隐藏工位搭子的数据保留在浏览器里，再升级回来能接着用（回滚测试已覆盖）。

## 5. 本机复现 PR 测试

```bash
npm ci && npm run typecheck && npm test
npm run buddy:rules && git diff --exit-code -- docs/
npm run build:static -- --base=/onstage-source
PAGES_BASE=/onstage-source npm run test:pages
node scripts/check-qr-target.mjs --local dist-pages
npm run test:rollback -- <V1.4.1 发布包解压目录> dist-pages
```

没有 Playwright 自带的 Chromium 时，设置 `CHROME_PATH=<本机 Chrome 路径>`。
