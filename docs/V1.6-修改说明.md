## 三、运营体验（深度版）的教学深度

保留 6 步结构，网址是 `/experiences/ops-returns-deep/`。

| 要求 | 怎么做的 |
|---|---|
| 5 个方法 | 第 2 步示范之后，列出这次要学的 5 个方法：<br>① 整体退货率用合计数算；<br>② 退货单数变多不一定是问题变严重；<br>③ 同时发生的变化不能直接证明谁是原因；<br>④ 写可验证的假设；<br>⑤ 选优先行动，并提前说好怎么判断有效。<br>每个方法都配一个具体例子。每道题旁边会提醒「这题用到哪个方法」。 |
| 示范和练习用不同材料 | 示范：手机壳颜色。热身题：两周数据，专门考「合计 vs 平均」。正式任务：刹车片适配。迁移练习：车载手机支架。四组材料互不相同。 |
| 可验证的假设 | 第 4 小步改成三格：「如果原因是……」「那么应该看到……」「如果看到……说明不成立」。 |
| 行动和效果 | 第 5 小步新增一格：看什么指标、多久以后看、变成多少算有效。 |
| 迁移练习 | 第 6 步：车载手机支架，订单涨了 2.5 倍，退货单数也涨了，但退货率没变；主管却认为是新包装的问题。学生要计算、判断，再写一个可验证的假设。**做完迁移练习才能保存成果**，不会只问一句「你觉得学会了吗」。 |
| 规则检查 | 只检查数字（前后退货率、热身题、迁移题）和学生选的标签（迁移题的判断）。<br>常见错误有专门说明，例如按平均百分比算出 6.5%。 |
| 三种反馈分开 | 「对照参考」页的开头写明：<br>规则检查只做机械比对；<br>参考思路是平台编写的一种做法；<br>**个性化点评没有提供**，系统不分析学生写的文字，也不按字数、关键词或完成次数评价。 |

## 四、第二个完整体验：AI 回答评测

标题：「两个 AI 回答，哪个更适合用户？做一份评测标准」。网址：`/experiences/ai-eval/`。同样是 6 步，复用同一套组件和成果结构，没有另做页面。

| 要求 | 内容 |
|---|---|
| 用户场景和任务 | 一位实习生用 Excel 2016 做 VLOOKUP，一半结果显示 #N/A，单元格有绿色小三角，明早要交。学生扮演 AI 学习助手团队的运营实习生，负责做评测。 |
| 必要知识和完整示范 | 示范换了一组材料：给初中生解释「天空为什么是蓝色」，3 个回答，对照 NASA 的资料核对。<br>示范之后列出 5 个方法：事实准确、任务完成、信息遗漏、场景决定标准的重要程度、每个判断要有两处证据。 |
| 可核验的参考材料 | 4 条 Microsoft Support 官方页面的摘要和链接：VLOOKUP、#N/A、文本格式的数字、XLOOKUP 在 2016 不可用。 |
| 有取舍的回答 | A：都对，但重点不突出、太长。<br>B：把错误藏起来，没有完成任务。<br>C：诊断最准，但把 TRUE 说成精确匹配（事实错误）。<br>D：推荐 XLOOKUP，在 Excel 2016 里不可用。<br>**没有完美答案**。 |
| 学生要做的 | 先弄清用户和任务；自己定评测标准和一票否决项；逐个评估，每个回答先选问题标签，再写证据；排序，说明取舍和怎么改；还要验证什么；迁移练习是换成 Microsoft 365 用户，看标准怎么变。 |
| 不是 A/B 选择题 | 标签只是辅助，可以「对照参考标注」做规则比对。核心判断和证据都要学生自己写。 |
| 标注 | 回答都标为「平台人工编写的教学样例，不是任何真实 AI 模型的输出」。审核状态：「未经 AI 产品或评测从业者审核」。 |

## 九、预览和部署

**预览**：看交付的截图（桌面和手机，都是实际运行截取）。如果需要在线预览、又不想影响线上，可以另建一个免费的预览仓库，例如 `shangchang-app/onstage-preview`，需要你同意后再建。注意：重新打包时要把网址前缀改成 `--base=/onstage-preview`。

**部署到线上**（需要你确认后再做）：

1. 使用交付的 `site.zip`。它就是本轮提交的打包结果，页脚和 `version.json` 里有提交号。
2. 打开 `github.com/shangchang-app/onstage` → `site.zip` → 删除，再 `Add file → Upload files` 上传新的 `site.zip`。或者直接上传同名文件覆盖。**仓库根目录只能有一个 .zip 文件。**
3. 提交后，在 Actions 页面等「Publish trial site」变成绿色（1–3 分钟）。
4. 打开 `https://shangchang-app.github.io/onstage/version.json`，确认 `version` 是 `1.6.0`，`commit` 和交付消息里的提交号一致。
5. 用手机打开 `/onstage/experiences/ops-returns-deep/`，走一遍，并保存一次成果。

**自己重新打包**（技术同事）：`npm ci && npm test && npm run build:static && npm run test:pages`，然后把 `dist-pages` 里的内容（不包括这个文件夹本身）打成 zip。
