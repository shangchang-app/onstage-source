# 上场 · 部署准备版修改说明（V1.4.1 → 1.4.1-deploy.1）

日期：2026-11-11
原来的 V1.4.1 交付保持不变，本版本单独存放。本版本**没有部署、没有上线**，也没有创建任何付费资源。
没有新增业务功能，只修改了部署所需的配置、安全和运维部分。

## 一、检查结论：原来的 V1.4.1 不能直接部署

逐项读了代码、依赖、数据库、登录、文件存储和启动方式，发现以下实际阻塞：

| # | 问题（原代码） | 后果 | 处理 |
|---|---|---|---|
| 1 | `npm start` 写死 `--hostname 127.0.0.1` | 只接受本机访问。托管平台从外部转发请求，网站会打不开 | 改为监听所有网卡；端口读取平台给的 `PORT` |
| 2 | 生产环境没有短信服务时，登录不可用；后台只能先登录、再用命令授权 | 线上**没有任何办法进入后台** | 新增「管理员一次性登录链接」，只能在服务器命令行生成 |
| 3 | 生产环境禁止写入演示数据，但线上数据库是空的 | 学生打开后看不到任何内容 | 新增可选配置 `DEMO_CONTENT=seed-if-empty`：只在空数据库写入一次，全部标为示例 |
| 4 | `DATABASE_PATH` 不设置时默认写到项目目录 `./data` | 大多数平台重新部署会清空项目目录，数据**全部丢失**，而且不会报错 | 生产环境必须设置持久化磁盘上的绝对路径，否则拒绝服务，并在日志写明原因 |
| 5 | 网站地址 `APP_ORIGIN` 不设置时默认是 `http://127.0.0.1:3000` | 线上所有保存操作都会被当成「来源无效」拒绝 | 可以填多个地址；不填时自动使用平台分配的 https 地址；生产环境检查必须是 https |
| 6 | 访客会话固定 7 天、不续期 | 学生第 8 天回来，草稿就看不到了 | 默认 30 天，每次打开自动续期 |
| 7 | 没有登录时，「保存完成记录」「收藏」仍然引导去登录页，而登录页显示不可用 | 学生走到最后一步卡住 | 没有开放登录时，改为直接说明试用版的保存范围，不再引导登录 |
| 8 | 没有健康检查、备份和恢复方式 | 平台无法判断服务状态，出问题后无法回退 | 新增健康检查；新增在线备份、恢复，以及升级前自动备份 |

**多实例与持久化**：
- SQLite 是一个文件，只能由**一个**服务进程使用，并且必须放在平台的持久化磁盘上。
- 推荐的 Render 方案满足这两点：挂了磁盘的服务平台不允许扩成多实例；部署时先停旧实例、再启动新实例，所以会有几秒停机。
- 不要部署到 Vercel、Netlify 这类无服务器平台，也不要部署到没有持久化磁盘的免费实例。

## 二、修改清单

**配置（`src/server/config.ts`，新增）**
- `APP_ORIGIN` 可以写多个地址（英文逗号分隔），方便以后换域名期间新旧地址同时可用。
- 不填 `APP_ORIGIN` 时，自动使用平台地址（Render：`RENDER_EXTERNAL_URL`；Railway：`RAILWAY_PUBLIC_DOMAIN`）。
- 生产环境启动检查：网站地址必须是 https；数据库路径必须是绝对路径。
  - 检查不通过时，健康检查和所有接口返回「服务配置不完整」，具体原因只写在服务器日志里，不对外暴露。
- `SESSION_DAYS`：会话有效期，默认 30 天，每次访问自动续期。

**登录与权限（`src/server/auth.ts`、`http.ts`）**
- 生产环境仍然**不允许**模拟验证码，没有测试账号。短信服务未配置时，登录接口返回 503。
- **管理员一次性登录链接**：
  - 在服务器上运行 `npm run admin:link -- 手机号` 生成。手机号只作为账号标识，不发短信。
  - 链接 15 分钟内有效，只能用一次；数据库只保存口令的哈希。
  - 口令放在网址 `#` 后面，不会进服务器访问日志；打开链接后要手动点按钮才登录，避免被聊天软件的链接预览自动用掉。
  - 登录后的管理员会话 12 小时后失效，不续期；登录时不会合并这台电脑上的访客草稿。
  - `npm run admin -- 手机号 --revoke` 可以取消管理员权限，并立即退出该账号的所有会话。
- 每个访客每分钟最多 240 次写入（正常自动保存远低于这个数），防止脚本刷写。
- **例行清理**（每小时最多一次）：
  - 清理过期会话、验证码、限流记录；
  - 清理「会话已过期、且超过有效期没有更新」的访客草稿（这些草稿已经没有人能打开）；
  - 已登录账号的数据不清理。

**数据库与备份（`src/server/db.ts`，`scripts/backup.ts`、`scripts/restore.ts`）**
- 迁移 005：会话续期标记、管理员登录链接表。
- `npm run backup`：在线一致性备份，网站运行中也可以做，备份后会做完整性检查。不会自动删除旧备份。
- `npm run restore -- 文件`：
  - 只把备份放到「待恢复」位置，下次启动时才替换，不会在运行中覆盖正在用的数据库；
  - 原数据库另存为 `.before-restore-时间`，不删除；
  - 损坏的备份会被跳过。
- 重新部署带来新的数据库迁移时，先自动备份一份。

**界面（只在「没有开放登录」时生效；接入短信后自动恢复原样）**
- 页头不显示「登录」，显示「试用版」。
- 作答页、体验详情、「我的」直接写明保存范围：「同一个浏览器 30 天内回来可以继续；换设备、换浏览器、清除浏览器数据、使用无痕模式都会看不到」。
- 「完成并保存记录」和「收藏」改为说明暂不可用，不再引导到打不开的登录页。
- 新增 `/login/link` 页面（管理员一次性登录用），网站上没有任何链接指向它。

**部署文件**
- `render.yaml`：Render 一键创建配置。新加坡机房，0.5c-512mb，1 GB 磁盘挂在 `/var/data`，健康检查 `/api/health`。
- `Dockerfile` / `.dockerignore`：给 Railway、Fly.io、自有服务器用，持久化目录 `/data`。
- `.node-version`：指定 Node 24。
- `.env.example`：重写，每一项都有说明。
- `robots.txt`：试用期默认不让搜索引擎收录（`ALLOW_INDEXING=true` 可以开放）。
- 文档 `docs/部署指南.md`：给非技术人员的分步操作，含费用、国内访问测试、备份恢复、绑定域名。

**测试**
- `tests/deploy.test.ts`：新增 8 项服务端测试。
- `npm run test:deploy`：新增部署前浏览器检查。用生产构建、生产模式启动，模拟持久化磁盘，分 3 个阶段，阶段之间重启服务器。

## 三、身份方案（本版本默认：访客模式）

| | 现在（未配置短信） | 以后接入手机登录 |
|---|---|---|
| 浏览、开始岗位体验 | 不用登录 | 不用登录 |
| 草稿自动保存 | 保存在服务器上，按访客的浏览器会话隔离 | 登录后保存到账号 |
| 跨设备继续 | 不支持 | 支持 |
| 完成记录 | 暂不能保存 | 支持 |
| 收藏 | 暂不可用 | 支持 |

**访客草稿的保存范围**：用同一个浏览器，30 天内回来可以继续（每次打开自动续期）。

**以下情况会看不到之前的作答**：
- 换手机或电脑、换浏览器；
- 清除浏览器数据（Cookie）、使用无痕模式；
- 连续 30 天没打开网站；
- 注意：微信里打开和手机浏览器里打开，算两个不同的浏览器。

**隔离方式**：每个浏览器第一次打开网站时，分到一个随机的访客身份（HttpOnly Cookie），所有草稿按这个身份读写。整个群共用一个网址，但不共用账号。

## 四、测试结果（环境：Ubuntu 24.04 云端容器，Node 22.23，Chromium 1243，Playwright 1.63.0）

把交付包解压到新目录，从 `npm ci` 开始运行。

`test:deploy` 的 9 项检查：
1. 生产模式不返回模拟验证码，登录接口返回 503；页面没有测试环境提示条；页头显示「试用版」。
2. 空数据库自动写入演示内容，全部标为示例，只写一次。
3. 两个访客用同一个网址，草稿互不可见，「我的」互不包含；页面显示试用版保存范围，没有登录和收藏入口。
4. 断网时显示「网络中断：作答已暂存在这台设备」，恢复网络后保存成功。
5. 后台权限：
   - 访客打不开后台、读不到后台接口，看不到后台入口；
   - 伪造口令被拒绝；
   - 服务器生成的链接可以登录后台，而且第二次使用被拒绝。
6. 网站运行中完成在线备份。
7. 重启后：访客草稿、管理员会话、内容都还在。
8. 恢复命令只准备恢复，不影响正在运行的网站。
9. 再次重启后数据回到备份时的状态，原数据库另存，没有删除。
