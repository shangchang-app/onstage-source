# 上场 V1.5 修改说明

日期：2026-11-11　版本：`1.5.0`　基于：线上免费试玩版 `1.4.1-free.1`（同一套代码，不是另起的展示站）

> 这一版**没有覆盖线上网站**。线上 `shangchang-app.github.io/onstage` 仍是 V1.4.1。确认后再按文末步骤发布。

## 一、这一轮做了什么

按你后来补充的方向（优先级高于第一份指令里的「复杂工作台」）：先把一个**短任务**做得自然、有收获，再给深度入口。

### 1. 旗舰体验改成 5–10 分钟的短闭环

网址不变：`/experiences/ops-returns/`。已经发出去的链接，打开的就是新版。

| 步骤 | 学生做什么 |
|---|---|
| 收到任务 | 运营负责人在群里发来一条消息，并给出 3 个数字：订单 +42%、估算净利润 −48%、退货率 4.7% → 11.1%。第一屏没有表单。 |
| 看材料 | 4 份短材料：利润拆解、退货原因前后对比、差评和适配表、第 4 周变更记录。点开才算「看过」；觉得重要的可以「标为关键」。不强制全看。 |
| 行动与理由 | 从 6 个行动里**组合**（可以多选），或写**自己的方案**；一两句理由；还缺什么信息（可选建议，也可以自己写）。 |
| 复盘 | 见下文。 |

选择题只用来帮新手起步。核心的「理由」和「自己的方案」都是自由文字，而且只写自己的方案也能完成。

### 2. 复盘：只根据操作生成，写明没有 AI

页面上直接写着：「根据你的操作生成……你自己写的方案和理由原样放在下面，系统没有接入 AI，不会自动分析这段文字。不打分，也不评价你适不适合这个岗位。」

| 复盘部分 | 根据什么生成 |
|---|---|
| 你的方案 | 原样展示学生选的行动、自己的方案、理由、缺的信息，以及看过几份材料。 |
| 合理的地方 | 学生选的每个行动和信息，各自针对了什么（数据依据）。 |
| 可能漏掉的 | 没选的核心行动、没打开的关键材料、没提的关键信息。如果学生写了自己的方案，会注明：「系统不会读你写的文字，如果你的方案已经包含这一点，可以忽略」。 |
| 要权衡的 | 每个行动的代价；一次改动太多时，会提醒「之后很难分清是哪一个起了作用」。 |
| 怎么知道有没有用 | 每个行动之后看什么数字、多久后看。 |
| 参考复盘 | 标为「系统参考，不是标准答案」。包含参考思路里也不确定的地方，以及一个自查清单（只给学生自己看）。 |
| 这份工作平时是什么样 | 典型一周；「这次做的事里你更喜欢哪些、不太喜欢哪些」。只给学生自己看，不变成标签。 |
| 想再往深走一步 | 同一情境的深度版（约 45 分钟），以及其他体验。 |

自动测试确认了一点：**理由不管写什么，规则反馈都一样**。也就是说，系统没有假装读懂了学生写的文字。

### 3. 深度版保留

原来 V1.4 的 6 步引导体验原样保留，改名为「深度版：退货率上升，写一页给主管的说明」，网址是 `/experiences/ops-returns-deep/`。它和短体验是同一个情境，数据也一致。

### 4. 首页

- 首屏：「先试着做一次工作，再决定要不要走这条路。」
- 场景预览：负责人消息 + 3 个数字 + 三步说明。
- 一个开始按钮：「开始 8 分钟体验」。
- 「可以试的工作」：先放短体验和深度版两张卡，每张写明时长、难度、成果。4 个简版练习收进一个小列表，写着「完整版本还在制作」。游戏版本反馈分析、AI 产品回答评测写成「正在规划（还不能体验）」，没有做空卡片。
- 「做完能得到什么」：附一份方案 + 复盘示例，标为「示例，平台编写，不是真实学生作品」。

### 5. 企业合作页

合作页包含这些部分：

- **五步流程**：企业提供场景 → 上场制作 → 企业审核 → 学生参与、平台汇总匿名数据 → 双方决定下一步。
- **素材清单**：企业需要提供什么，以及不需要、也不会要什么。
- **体验内容样例**：以旗舰体验为例。
- **学生成果样例**：标为示例。
- **匿名汇总报告样例**：标为示例。报告里写明「以下数字全部是虚构的」；生成真实报告需要正式版和学生同意，现在的试玩版不收集任何学生数据。
- **合作意向**：试玩版没有接收服务，所以写「在线提交暂未开通（待配置）」，不放提交按钮。可以配置外部问卷地址，见下文。
- 页面写明「目前上场还没有合作企业」，没有出现 TiMi 或任何 AI 公司的名字。

### 6. 数据与来源

体验第一页有「这些数据从哪来？」，每份材料也都标了类型：

| 类型 | 内容 |
|---|---|
| 模拟教学数据 | 店铺、商品、6 周数据、评论、适配表、变更记录；费用参数也是模拟的 |
| 根据公开资料改编 | 「适配信息」的说明，来源：[eBay Seller Center](https://www.ebay.com/sellercenter/listings/list-with-fitment)；「广泛匹配 / 精确匹配」的说明，来源：[Amazon Ads 指南](https://advertising.amazon.com/library/guides/targeting-with-sponsored-products)。2026-11-11 查阅，做了简化。 |
| 企业授权共创 | 本体验没有 |

所有数字都核算过，见 `docs/V1.5-数据核算.md`，由 `tests/quick.test.ts` 自动重算。

  - 首页内容齐全，所有链接都带子路径。
  - 专属链接、深链接（带或不带结尾斜杠）可以直接打开，刷新也正常。

## 四、哪些是真的，哪些是示例，哪些要配置

| | 内容 |
|---|---|
| **真实可用的功能** | 4 步短体验、规则复盘、深度版、简版练习；作答自动保存在学生自己的浏览器里（同一浏览器 7 天内可以继续）；打印 / 存为 PDF；机会库浏览 |

## 五、发布到线上（需要你确认后再做）

1. 用测试环境里已经打好的 `site.zip`，或者重新打包：`npm ci && npm run build:static && npm run test:pages`，再把 `dist-pages` 里的内容打成 zip。
2. 在 GitHub 仓库 `shangchang-app/onstage` 里替换根目录的 `site.zip`，根目录只保留一个 zip。Actions 会自动发布。
3. 如果要开放合作意向：先建好问卷，打包时加上 `NEXT_PUBLIC_COOP_URL=问卷地址`。
