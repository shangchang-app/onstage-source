## 2. 已完成

**岗位体验（学生端）**
- 导航：首页｜机会库｜岗位体验｜企业｜我的（手机为底部导航）。
- 首页：主推「不用等到实习，先体验一次真实岗位场景」，下面是岗位体验、实习与校招、赛事、企业合作入口。
- 体验列表显示这些信息：方向、时长、入门程度、将体验的工作、平台制作 / 企业共创、示例标记。
  - 「完整引导」排在前面。
  - 简版练习明确写着「完整引导版本还在制作中」，不伪装成完整体验。
- 详情页显示：6 步流程、时间、能学到什么、「不是实习、能力认证或录用保证，也不是投递门槛」。
  - 有草稿时按钮变为「继续体验」，并显示上次停在哪一步。
- 作答页（6 步，约 45 分钟，不计时）：
  - **认识岗位 → 看一次示范 → 接到模拟任务 → 跟着尝试 → 对照参考思路 → 总结与下一步**
  - 步骤条分别显示：已浏览 / 已作答 x/10 / 未看。可以前后翻步、随时看参考。
  - 「模拟工作场景」标注；材料都是虚构的。
  - 作答有逐条提示、答题框架和术语解释，只用文字和多选，不用上传文件。
  - 参考页提供：参考成果、为什么、其他合理做法、常见误区、还缺的信息、自查清单（不保存、不打分）。不做关键词判断，不贴「适合 / 不适合」标签。
  - 总结页：问了解多少、喜欢哪部分、不喜欢什么、接下来想了解什么；推荐相关岗位、体验和企业。
  - 完成记录写明「只表示完成模拟体验，不代表实习或职业资格」。
- 示范内容：跨境电商运营「商品退货率上升，先查什么？」。6 周虚构数据、退货原因、5 条评论、第 4 周的 3 项变更，共 6 个小步作答。
  - 参考思路允许不同判断。
  - 没有编造从业者姓名、头像或经历。
- 我的：继续体验、完成记录、收藏、可恢复的作答。不展示排名，不对企业公开。

**数据、账号、权限**
- 服务端账号：手机号验证码登录，模拟短信只在开发 / 测试环境可用，生产环境没有固定验证码或回退。
- 会话、角色（学生 / 管理员）和归属检查：
  - 草稿、记录、恢复副本只能本人读写。
  - 后台接口只对管理员开放，而且不返回任何学生的作答（只有匿名数量）。
  - 企业端不开放作答查看。
- 草稿：
  - 自动保存（0.7 秒防抖）；失败后指数退避重试，期间作答在本机暂存。
  - 关页后再打开，会提示恢复本机内容。
  - 浏览器存储不可用时给出明确提示。
- 冲突处理：
  - 同账号两个页面同时改：两份都保留，由学生选择继续哪一份，另一份进入「可恢复的作答」。
  - 另一个页面只是翻步骤、或服务器草稿还没有作答：合并进度，不误报冲突。
- 游客登录合并规则（登录页上写明）：
  - 账号里没有草稿 → 并入。
  - 两份相同 → 保留账号的。
  - 两份不同 → 进入冲突，由学生选择。
  - 账号已完成这个版本 → 放进可恢复区。
- 多标签页切换账号：旧页面弹出提示，保存和提交暂停，不会静默换账号；服务端也拒绝旧会话的写入。
- 完成：绑定账号和内容版本，同一版本不会重复生成记录。只浏览、不作答，前端和服务端都不会生成记录。

**版本、下线、后台**
- 体验内容按版本管理：草稿 → 提交审核（必须写内容来源） → 审核通过 → 发布。
  - 已发布 / 已替代的版本由数据库触发器禁止修改。
  - 新版本发布后，历史完成记录仍对应原版本快照，页面会提示「后来更新到第 N 版」。
  - 正在做旧版本的学生可以做完；新来的学生拿到新版本。
- 「平台制作 / 企业共创」：企业共创必须关联企业，并记录企业的实际确认（确认人职务、方式、日期）才能发布。没有确认，不显示任何企业背书。
- 体验下线：不能继续保存或完成；草稿和记录保留；重新上线后可以继续。
- 后台标签页：
  - 岗位体验内容：版本、审核、发布、下线、匿名汇总。
  - 招聘 · 赛事 · 企业：记录确认、发布、下架。
  - 合作意向：状态为待联系 / 已联系 / 暂不合作 / 已合作。
  - 反馈处理、操作记录。

**企业合作页**
- 价值说明，以及流程：企业提供岗位背景与脱敏场景 → 平台协助制作 → 企业确认后发布。
- 写明「不承诺人数、招聘结果或自动筛选」「企业看不到个人作答」。
- 意向表单要求勾选联系方式用途，提交后保存到数据库，显示「待联系」状态。

**招聘专区**：V1.3.1 的规则全部沿用，并通过回归测试：
- 修改后回到「待企业确认」；未确认不能发布，未确认的改动不会出现在公开页。
- 示例投递只给演示说明，过期自动截止，支持反馈失效信息，收藏需要登录。

## 3. 测试结果（真实运行）

- `npm run typecheck`：通过
- `npm run build`（生产构建）：通过
- `npm test`：服务端规则测试 **13 / 13 通过**
- `npm run test:e2e`：浏览器验收，**16 / 16 通过**。环境：Playwright + Chromium + 本地开发服务器，独立测试库，详见 `test-results/acceptance.json`。覆盖：
  1. 零经验学生以游客身份走完 6 步，登录后作答并入账号，保存完成记录
  2. 只浏览不作答：按钮不可用，服务端也拒绝提交
  3. 自动保存，刷新后回到原步骤和作答
  4. 登录合并时两份不同：不覆盖，选择后另一份进入可恢复区
  5. 同账号两个页面同时修改，出现冲突并完成恢复
  6. 网络中断：本机暂存、自动重试；关页后重新打开，可恢复本机内容
  7. 浏览器存储不可用：显示提示，仍保存到服务器
  8. 多标签页切换账号：旧页暂停，旧会话写入被拒（409）
  9. 账号隔离：他人记录 404、学生访问后台 403、后台数据和版本数据里不含作答、管理员也读不到学生记录
  10. 内容更新：通过后台页面完成新建版本、编辑、审核、发布；旧版本改动被拒；旧版草稿可以做完；历史记录不变；新学生拿到新版
  11. 下线 / 重新上线
  12. 企业合作意向：校验、同意项、保存，后台改状态
  13. 招聘专区回归
  14. 键盘与焦点：第一个 Tab 是「跳到主要内容」；弹窗内焦点循环，背景设为 inert；Esc 关闭后焦点回到原按钮；切换步骤后焦点移到标题
  15. 系统「减少动态效果」偏好下，过渡被关闭
  16. 390px 和 320px 宽度下，11 个页面加作答页 6 步都没有横向滚动，并截图

## 4. 本轮做出的取舍（我自己决定的）

1. 游客草稿保存在服务端的游客会话里（沿用 Codex 设计），另在浏览器本机做备份，用于断网和意外关页。
2. 「感受」（总结页）先保存在本机，完成时一起写进记录；登录时随游客作答一起带到账号。
3. 简版练习的参考答案只在完成记录里显示，作答时不提供，避免只看答案。
4. 后台编辑体验内容用 JSON 文本框加服务端校验（章节、材料、提示、参考都有结构校验）。没有做可视化编辑器。
5. 管理员只能用本机命令 `npm run admin -- 手机号` 授予，网站上没有授权入口。
6. 后台只显示匿名数量（草稿数、完成数），不显示任何人的作答或名单。

## 6. 上线前的阻塞项

1. **短信服务**：需要选定并开通短信服务商，按其接口调整 `HttpSmsProvider`，配置网关地址和令牌（本轮没有购买任何服务）。
2. **密钥与 HTTPS 域名**：设置 `AUTH_SECRET`；准备正式域名和证书，`APP_ORIGIN` 设为正式地址。
3. **托管与备份**：SQLite 需要单实例、持久磁盘、定期备份。如需多实例，要换成服务端数据库。
4. **合规**：用户协议、隐私政策（个人信息保护法），以及境内部署的 ICP 备案。页面上目前只有简短的隐私说明，没有正式协议文本。
5. **真实内容**：
   - 生产库不会写入演示数据，上线前需要准备真实内容的录入方式（见上面的后台新建表单）。
   - 示范体验建议请真实从业者审阅，审阅人信息经本人同意后再展示。
6. **企业关系**：任何「企业共创」或真实岗位都必须先取得企业的实际确认。演示数据里的企业都是虚构的。
7. **兼容性与无障碍**：上线前补测 Safari / iOS、Android 真机和屏幕阅读器。
